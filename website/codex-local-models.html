Codex 高级配置

本地模型（离线白嫖）· 自定义云驱动（接任意 OpenAI 兼容接口）

U-King 默认已经帮你把 Codex 接好了国内可用的虾盘云驱动，开箱即用、不用配。这页是给想自己折腾的进阶用户：

  • 方案 A · 本地模型：用自己电脑的显卡跑开源大模型，完全离线、不花一分钱、数据不出本机。需要还不错的显卡/内存。
  • 方案 B · 自定义云驱动：把 Codex 接到任意 OpenAI 兼容的接口（你自己的代理、公司内网、别家 API），灵活但要懂一点配置。

本页基于 OpenAI 官方文档 Codex Config · OSS mode & local providers 整理，并结合 U-King 的国内环境。

📌 不知道选哪个？ 想省事直接用 U-King 默认的虾盘云就好（这页可以不看）。想离线/省钱/隐私→看方案 A；想接自己的 API→看方案 B。

A方案 A：本地模型（codex --oss，离线白嫖）

Codex 自带 --oss 开关，能直接连本机跑的开源模型（通过 Ollama 或 LM Studio），全程不联网、不用 API Key。

⚠️ 对电脑有要求：本地跑大模型吃显卡显存 / 内存。7B 小模型至少 8GB 内存能跑（慢），想流畅建议 16GB+ 内存或 8GB+ 显存的独显。配置一般的电脑会很慢甚至跑不动 —— 这种情况还是用 U-King 默认的虾盘云云端模型更实在。

第 1 步 · 装 Ollama（本地模型运行器）：

⬇ Ollama 官网下载（Windows）

下载双击安装。装完它会在后台常驻（任务栏有个羊驼图标）。

第 2 步 · 拉一个开源模型：打开 U-King 内置终端（或 CMD），拉个模型。推荐国产 Qwen（通义千问），中文好、对代码友好：

# 拉 Qwen 2.5 的 7B 代码版（约 4.7GB，按你电脑配置选大小）
ollama pull qwen2.5-coder:7b

# 配置低？拉更小的 3b（约 2GB）：ollama pull qwen2.5-coder:3b
# 配置高？拉 14b/32b 效果更好但更吃显存

第 3 步 · 在 U-King 终端里用 Codex 连本地模型：

# --oss 走本地 Ollama，-m 指定刚拉的模型
codex --oss -m qwen2.5-coder:7b

就这样，Codex 现在跑在你自己电脑上了，完全离线。

（可选）写进配置，下次免敲参数：编辑 %USERPROFILE%\.codex\config.toml，加上：

oss_provider = "ollama"        # 默认本地运行器；用 LM Studio 就写 "lmstudio"
model = "qwen2.5-coder:7b"     # 默认模型

以后直接 codex --oss 即可。

💡 想换 LM Studio（带图形界面、更易上手）也行：装 LM Studio → 在里面下载模型 → 开它的「本地服务器」→ 上面配置里 oss_provider 改成 "lmstudio"。

B方案 B：自定义云驱动（接任意 OpenAI 兼容接口）

想让 Codex 走你自己的 API（自建代理、公司内网、别家兼容 OpenAI 的服务），用 Codex 的 model_providers 机制。U-King 配虾盘云用的就是这一套 —— 你照葫芦画瓢改成自己的即可。

编辑配置文件：%USERPROFILE%\.codex\config.toml（不存在就新建）。写法：

# 用哪个 provider + 哪个模型
model = "你的模型名"
model_provider = "myapi"

# 定义这个 provider 的连接信息
[model_providers.myapi]
name = "我的自定义 API"
base_url = "https://你的接口地址/v1"
env_key = "MY_API_KEY"          # API Key 从这个环境变量读（见下）
wire_api = "responses"          # ★新版 Codex 多只认 "responses"；普通 chat/completions 服务用 "chat"

再设置 API Key 环境变量（上面 env_key 指向的那个）。在 U-King 终端 / PowerShell：

# 永久写入用户环境变量（重开终端生效）
setx MY_API_KEY "sk-你的密钥"

重开终端后敲 codex 就走你自己的 API 了。

字段速查

字段作用
model用哪个模型（名字由你的 API 决定）
model_provider用上面定义的哪个 provider（不能叫保留名 openai）
base_url接口地址，一般以 /v1 结尾
env_key从哪个环境变量读 API Key
wire_api协议：responses（新版 Codex CLI/桌面版多只认这个）或 chat（普通 OpenAI chat/completions 服务）。连不上就两个都试试
💡 U-King 默认的虾盘云就是这么配的（base_url 指向 api.u-claw.org/v1）。你在「AI 设置」里也能不碰配置文件直接加自定义 provider —— 那个图形界面比手改 toml 省事。
⚠️ 改了 config.toml 后，U-King 的「一键配好全部 / 切驱动」可能会覆盖你的手改（它整文件接管 Codex 配置）。想长期用自定义 API，建议在 U-King「AI 设置」里加 provider，而不是手改文件。

❓ 常见问题

本地模型和虾盘云云端模型，差别大吗？
差别明显。云端（虾盘云默认的 deepseek-v4-pro 等）是几百 B 的大模型，又快又聪明，但要联网、按量计费。本地开源模型（7B/14B）能离线白嫖、隐私好，但能力弱一截、速度看你显卡。日常重活建议云端，离线/保密场景用本地。
codex --oss 报连不上 / 超时？
确认 Ollama 在后台运行（任务栏羊驼图标），且模型已经 ollama pull 下来了。可先单独测：终端敲 ollama run qwen2.5-coder:7b 能对话，说明 Ollama 正常，再回头用 codex --oss。
电脑配置一般，能跑本地模型吗？
8GB 内存能跑 3B 小模型但慢；16GB 内存 / 8GB 显存独显跑 7B 比较舒服。配置不够别硬上 —— 直接用 U-King 默认的虾盘云云端模型，体验好得多。
自定义 provider 配好了，codex 却还连虾盘云？
多半是 U-King 的「切驱动 / 一键配好全部」又把 config.toml 覆盖回去了（它整文件接管 Codex 配置）。正解：在 U-King「AI 设置」里用图形界面添加自定义 provider 并切到它，别手改文件，这样不会被覆盖。
config.toml 在哪？怎么编辑？
在 %USERPROFILE%\.codex\config.toml（用户目录下隐藏的 .codex 文件夹）。文件资源管理器地址栏粘 %USERPROFILE%\.codex 回车进去，用记事本打开 config.toml 即可；没有就新建一个。
