# U-King 工作台（uking-workbench）

## 这个技能解决什么

客户手上是一个乱文件夹。AI 每次进去都要重新搞清楚「这堆是什么、该往哪写」，
于是每次都问一遍、每次都放错地方。

工作台 = 给这个文件夹一份**约定**（每个目录放什么、怎么命名、什么规矩），
再把约定编译成各家 AI **进目录时自动加载的那个文件**：`AGENTS.md`（Codex / Hermes 读）
和 `CLAUDE.md`（Claude Code 读），外加一份完整说明书 `WORKBENCH.md`。
之后任何 CLI 进来，不用谁提醒就知道该干什么、往哪放。

🔴 **入口文件名是有讲究的，不是随便起的。** 2026-08-11 前我们只落 `WORKBENCH.md` ——
而没有任何 CLI 会自动读这个名字，客户搭完工作台 AI 进去照样一问三不知。
这也是「每个项目的要求分开记」的办法：约定在各自的文件夹里，不在全局那一份记忆里，
所以项目之间不串。

🔴 **工作台不是一个网页，也不是一套固定模板。** 预置模板换个职业就不合身，
而「不合身但看着像能用」比没有更糟。所以**每次都按这个客户现搭**。

🔴 **这个技能自己不写任何文件。** 建目录、写说明书、三道安全闸门全在 U-King 的动作核心里，
你只负责**把这个客户的情况搞清楚，然后写出一份合格的 manifest**。
理由很直接：写在提示词里的「别覆盖客户的文件」，模型有一天就是会覆盖；写进动作核心它绕不过去。

## 先找到 U-King

```bash
UK="$HOME/.uking/U-King.exe"          # 装到本地后的默认位置
[ -x "$UK" ] || UK="$(command -v u-king-mini || true)"
```

找不到就直接告诉客户「这台机器上没找到 U-King，这个技能要靠它落盘」，**别自己 mkdir 顶上**——
那就是绕开闸门的第二份实现。

## 四步，别跳

### 第 1 步：只读盘点，拿事实不拿印象

```bash
"$UK" action run runtime.workbench.scan --json --input '{"path":"<他指的文件夹>"}'
```

回来的是：文件类型分布、各多少个、最近 30 天动过多少、目录多深、最大的几个子目录，
外加 `files`（**样本量**）和 `truncated`。

- 🔴 它**只 stat 不读内容**。你也别自己去 `cat` 他的文件 —— 你还不知道哪些是隐私。
  真需要读某几个，先问他哪几个能读。
- 🔴 **不许拿他机器上的使用记录**（别家 AI 的会话、用量统计、行为时间轴）当依据。
  那些数据 U-King 有，但用它替客户做决定是越界的。依据只能是**他指的这个文件夹** + **他亲口说的话**。
- `truncated: true` = 扫到上限就停了，**「没看到」不等于「没有」**，跟他说清楚。

### 第 2 步：问，但不超过 4 句

盘点已经回答了「他有什么」，你要问的是盘点看不出来的：

1. 你主要产出什么？（稿子 / 报表 / 图 / 合同 / 代码……）
2. 做完给谁？（自己看 / 发客户 / 发平台）
3. 现在哪一步最烦？
4. 有没有绝对不能动的目录？

**盘点能看出来的绝不问**。他刚指给你 300 个 PDF，你再问「你是不是有很多 PDF」，
他会觉得你没在看。

### 第 3 步：写 manifest

```json
{
  "schema_version": 1,
  "id": "<英文短名>",
  "name": "<中文名>",
  "one_liner": "<一句话说清这个台子干什么>",
  "for_whom": "<写**这个客户自己**的情况，不是写一个画像>",
  "dirs": [{
    "path": "01-xxx", "label": "…", "purpose": "…",
    "rule": "…", "naming": "…", "fed_by": ["uking-web"]
  }],
  "skills": [{ "id": "uking-web", "why": "<在**这个台子里**它具体干嘛>" }],
  "actions": [{ "id": "collect", "label": "…", "hint": "…",
                "prompt": "…", "needs": ["uking-web"] }],
  "not_included": ["<他问过但做不到的，一条一句>"]
}
```

硬规矩（**动作核心会当场校验，写坏了会被打回来并告诉你哪一条错**）：

| 规矩 | 为什么 |
|---|---|
| **目录 ≤ 6 个** | 多了他记不住，记不住就不会用，不会用就退回原来那个乱文件夹 |
| **每个目录都要有 `rule`** | 光有名字等于没有约定。「只进不改」「必须写出处」这种才算 |
| **`naming` 要具体到能照着起名** | 写「按日期」没用，写 `YYYY-MM-DD-来源-标题.md` 才有用 |
| **`path` 不许带 `..`、绝对路径、盘符** | 会写到工作台外面去 |
| **技能只能挑真实存在的** | 编一个不存在的名字，客户照着说明书喊一句，什么都不会发生 |
| **`not_included` 必须填** | 空着 = 默认什么都行，他用两天才发现，比一开始说清楚糟得多 |

想看一份写好的长什么样（**学形状，别抄内容** —— 那是个写公众号的人，客户很可能不是）：

```bash
"$UK" action run runtime.workbench.inspect --json      # templates[] 里就是内置样例
```

### 第 4 步：先预览，再落盘

```bash
# 预览：一个字节都不写。校验不过会把每一条错列出来，改完再来
"$UK" action run runtime.workbench.inspect --json \
  --input '{"path":"<工作台根>","manifest":<你写的那份>}'

# 客户点头后再真装（写动作，--yes = 显式确认这台机器可以被改）
"$UK" action run runtime.workbench.install --yes --json \
  --input '{"path":"<工作台根>","manifest":<同一份>}'
```

**预览打印的就是点确认之后真会干的事**（同一份计划，不是另写一套模拟）。

工作台根**通常不是他刚才指的那个乱文件夹** —— 动作核心会拒绝非空目录（也拒绝盘根和家目录，
**故意没有强制覆盖**）。让他新建一个空文件夹，或者在那个乱文件夹里新建一个子文件夹当根。

## 绝对不许做的

1. **不搬他的文件。** 只建新目录 + 写说明书。哪些老文件该挪到哪，**写成建议给他看**，
   他自己挪，或者明确说「你帮我挪」再动。那堆文件里有你不知道的依赖关系。
2. **不自己 mkdir / 写 WORKBENCH.md。** 落盘只有一条路：`runtime.workbench.install`。
   绕过去，三道闸门就白设了。
3. **别一次给他 12 个目录和 20 个动作。** 先给能用的最小一套，用起来了再加。

## 能挂哪些技能

跑一次拿这台机器上**准确的当前清单**（别背，它会变）：

```bash
"$UK" action run runtime.stack.inspect --json
```

U-King 随应用发的那批以 `uking-` 开头，覆盖：网址取正文 · 带登录态的浏览 ·
读别人发来的 Office/PDF · **改**他已有的 Office 不丢格式 · 看图 · 作图/视频/配音 ·
**从零写** Word/Excel/PPT · CAD 图纸 · 邮件草稿（只写不发）· 多 AI 协同。

🔴 **改现有 Office 文件和从零写新文件是两个技能，别搞反** —— 搞反了会把客户辛苦排的版
重新生成一遍，格式全丢。

## 做完跟他说什么

三句，别多：

1. 建了哪几个目录、各干什么（**说人话，别念说明书**）
2. 下次怎么用：`cd 工作台 && claude`（或 `hermes` / `codex`）—— 进去就行，
   AI 会自动读到约定，**不用他每次提醒**。若返回里带了 `warnings`，照着念给他听：
   那说明入口文件是他自己的、我们没覆盖，AI 读不到这个台子的约定
3. **哪些事这个台子干不了**（就是 `not_included` 那几条）—— 先说清楚，比他用两天才发现强
