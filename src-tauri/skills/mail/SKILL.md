# U-King 写邮件（uking-mail）

## 何时用
用户要发一封邮件 —— 催款、报价、通知、汇报、道歉、投诉、请假、跟进、邀约、附件转交。

## 核心用法
1. 先把要带的**附件生成好**（表格走 `uking-xlsx`、文档走 `uking-docx`、图纸走 `uking-cad`）。
2. 用 write_file 写 mail.json：
```json
{
  "to": ["张经理 <zhang@abc.com>"],
  "cc": ["财务部 <fin@corp.com>"],
  "subject": "关于 3 月货款的付款提醒",
  "text": "张经理：\n\n您好。\n\n附件是 3 月对账单，合计 188,790 元，账期已于 4 月 15 日到期……\n\n顺颂商祺\n李伟 / 采购部\n2026-08-04",
  "attachments": ["3月对账单.xlsx"]
}
```
3. `node ~/.uking/skills/uking-mail/scripts/gen-eml.mjs --in mail.json --out 催款函.eml --json`
4. 把 `.eml` 路径给用户，并**明确告诉他：这是草稿，双击用邮件客户端打开、确认无误后自己点发送**。
   想直接弹出来给他看就加 `--open`。

## 写邮件的要点（这才是本包值钱的地方，不是那个脚本）
- **主题要能单独成立**：收件人在几十封未读里只看得到主题。「关于 3 月货款的付款提醒」✅ ／「你好」❌
- **第一句就说事**：中文商务邮件别用三段寒暄铺垫。称呼 → 一句话说清目的 → 细节 → 明确的下一步。
- **要有明确的 ask 和期限**：「请于 8 月 10 日前安排付款」比「请尽快处理」有用十倍。
- **数字和附件对齐**：正文里写的金额/数量，必须跟附件里的一致。**先算清楚再写，别在正文里心算。**
  金额一律从附件数据里取，写完自己核一遍。
- **落款完整**：姓名 / 部门 / 日期 / 联系方式。
- **语气跟关系匹配**：催款给老客户用「提醒」，给拖了三个月的用「函」；道歉不要辩解。
- 不确定收件人邮箱就**留空并问用户**，绝不编一个地址填进去。
- 🔴 **收件人/主题里有换行会被直接拒绝生成**（报「邮件头里有换行或控制字符」）。这不是脚本坏了：
  邮件头一行一个头，值里的换行会变成一个**真实生效**的新头（比如凭空多一个 `Bcc:`），
  用户在邮件客户端界面上看不出来，点发送就抄给了第三方。你从文档/网页里提取收件人时尤其要注意 ——
  遇到这个报错，把那个字段里的换行去掉重来，别想办法绕过去。

## 附件
`attachments` 写路径即可，脚本自动判 MIME、base64 编码。**附件文件必须已经存在** ——
路径写错脚本会直接报错退出，不会生成一封「说好有附件但其实是空的」邮件。

## 边界：本包不发信
生成的是草稿文件，`sent` 永远是 `false`。不接 SMTP、不碰用户的邮箱密码、不代发。
用户问「能不能直接发出去」→ 如实说不能，理由是发信不可撤回、必须由本人确认。
要群发/自动发的场景，让用户在自己的邮件客户端或企业系统里做。
