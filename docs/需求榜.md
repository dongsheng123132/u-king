## P0 · 远端更新与配置的签名信任链（2026-09-04，Sol 代码审查）

当前多镜像只解决可用性，不能替代内容可信性：远端版本/skill 清单可按“合法 JSON 且版本更高”覆盖内嵌
清单，而这些清单包含后续安装和执行指令；现有二进制检查不足以证明来源可信。多个镜像若没有独立签名，
只是在扩大同一份未验证内容的来源面。

- **为什么尚未做**：需要重新设计升级、运行时清单与远端配置的统一信任根，并处理旧客户端、离线回退和
  密钥轮换；不能把 HTTPS、同源 hash 文件或“能解包”误当作签名验证。
- **落地方式**：定义带 `key_id` 的签名清单，覆盖版本、平台、全部镜像、文件大小、SHA-256 和远端配置
  摘要；客户端内嵌公钥，只在签名、摘要、版本和镜像字节全部一致时才接受。验证失败时继续使用内嵌配置
  或已验证旧版，拒绝执行远端内容。
- **验收**：自动覆盖篡改清单、篡改包、陈旧镜像、伪造高版本、镜像字节不一致、配置摘要不一致和密钥轮换；
  Windows 还核发行者签名，macOS 还核 Developer ID/Team ID。私钥只由发布基础设施保管，不进仓库、
  客户端或日志。

公开 README 宣称支持 Windows/macOS，但当前 macOS 跑道以构建和无头自检为主，不能证明真实用户能下载、
通过系统安全提示、启动 GUI 并使用终端。未取得本版本真机证据前，不能把“能构建”表述成“已支持”。

- **为什么尚未做**：需要真实 Apple Silicon 环境、发布产物及系统签名/公证状态，CI 无头构建无法替代。
- **验收**：从公开下载产物开始，在真实 Apple Silicon Mac 覆盖 Gatekeeper、首次启动、向导、工具安装、
  供应商配置与真实连通、PTY、中文输入/粘贴、窗口切换、升级、重启后的状态保留；Intel 至少补真机验证，
  或在发布页明确 Rosetta 支持边界。发布页同时提供实际 dmg/zip、哈希和签名/公证结论；脱敏验收记录提交本仓。
- **发布纪律**：上述条件不具备时，收窄 README 和下载页的 macOS 声明为实验性支持或暂不提供，而不是继续
  沿用完整支持的宣传。

## P1 · 应用内终端演进（2026-09-03）

### 1. xterm.js 6 独立升级验证

当前继续使用 xterm.js 5.5。Codex 的历史内容不可滚动主要来自 TUI 的备用屏幕、鼠标报告和局部重绘协议，
不是 xterm.js 的单点 bug；`codex --no-alt-screen` 只是兼容性缓解，不承诺所有 TUI 输出均可回滚。

- **为什么尚未做**：xterm.js 6 涉及 viewport/scrollbar 的大版本改动，不能与日常功能修复混合发布。
- **落地方式**：在独立分支匹配升级 `@xterm/xterm`、`@xterm/addon-fit`、`@xterm/addon-webgl`；失败只回退
  该实验分支，稳定终端不受影响。
- **验收**：Windows 真机 + Tauri WebView2 上验证 PowerShell 历史滚动/选择/复制，`codex`、`codex --yolo`、
  `codex resume` 的长输出、缩放、标签切换与退出，Claude Code/OpenCode/Pi 的交互、粘贴和备用屏，中文 IME、
  宽字符和混排，WebGL→DOM 回退，以及反复开关终端的 PTY/监听器清理；既有终端跑道、TypeScript 和 Rust
  终端测试均须通过，并补足新增行为的自动化断言。

### 2. 候选终端 A/B 样机

- **wterm（优先）**：仅以 feature flag 接入，复用同一 Rust PTY、输入和 resize 协议；验证 DECSTBM 局部滚动、
  中文 IME、宽字符、Codex 鼠标和粘贴。所有验收通过前不得成为默认终端。
- **Ghostty Web（第二候选）**：先证明 Windows WebView2、WASM 包体、中文输入和交互式 CLI 的完整可行性，
  再决定是否样机。
- **为什么尚未做**：候选库的上述兼容性尚无 U-King 的 Windows 真机证据；直接替换会同时承担渲染、输入、
  可访问性与会话稳定性风险。

WezTerm/Alacritty 等原生终端项目不是可直接嵌入的 Web 组件；除非另立“原生终端渲染重构”需求，否则不纳入
本轮决策。

### 发布判定

- xterm.js 6 全部验收通过，才可进入默认终端，并保留可回退版本和真机记录。
- 若升级未通过而当前版本可用，继续维持 xterm.js 5.5 + Codex 启动参数缓解，不对外宣称已彻底解决 TUI 历史。
- 仅当候选样机的完整验收、包体、性能和可访问性均不劣于基线时，才可提出替换 xterm.js 的发布方案。

## P1 · 工作台活跃终端上下文（2026-09-04，Sol 代码审查）

“拉出终端”、终端旁文件栏和终端内相对路径当前均以工作台根目录为准，而不是活跃终端标签的真实 cwd；
“拉出”实际上会新建 PTY，不是迁移当前会话。这会在用户于终端执行 `cd` 后悄悄打开错误目录。

- **为什么尚未做**：目前只保存 PTY 的启动 cwd，无法可靠得知交互 shell/TUI 执行 `cd` 后的实时目录；
  把启动 cwd 假装成当前 cwd 属于静默错误。
- **落地方式**：为每个终端标签维护经验证的当前 cwd；优先采用 shell integration / OSC 7 等明确协议，
  不支持时标为未知而非猜测。拉出窗口、文件栏和相对路径解析均只消费该活跃标签状态。
- **验收**：多标签进入不同目录并切换后，拉出、文件栏、相对路径解析均跟随活跃标签；执行 `cd` 后更新。
  cwd 未知、目录已删除或协议不支持时明确提示并回退工作台根目录。覆盖 Windows PowerShell、macOS zsh、
  标签切换和独立窗口参数测试。

## P1 · 现有 Free Router 下载完整性校验误拒绝（2026-09-06，源码审视）

- **问题**：`freerouter.rs::install` 把 certutil/shasum 返回的十六进制摘要文本再次逐字节转十六进制，
  64 位变 128 位，即使正确摘要也无法匹配。已隔离复现，不是下载网络不稳。
- **为什么尚未做**：本次为文档交接，未与正在施工的会话并行修改业务代码。
- **最小改法与验收**：复用 `installer::sha256_hex_bytes`，删除重复进程/解析路径；预期摘要非法时拒绝，
  不跳过校验。正确字节通过、篡改与非法预期摘要失败；再补真实安装证据。

## P2 · 借鉴 EchoBird：免费模型 Auto Router + 本地大模型页（2026-09-06，用户点名）

> 下列为外部实现调查，不代表全部架构已批准照搬。实施前按顶部审视文档核对本仓已有 Free Router/协议桥，
> 明确复用或替换关系；“固定 relay”“唯一务实解”“首个非空 chunk”“8–10 个候选”均需收窄或验证。

EchoBird v5.6.9 上了「免费模型 Auto Router」：一个本地地址同时供 OpenAI 与 Anthropic 协议，
一键接入至多 20 个免费模型供应商，按限速/服务异常/首字节超时/可用状态自动切换，带冷却与临时记忆
减少重复探测。用户点名「这个不错」，另点名其「本地大模型」页做得好。源码在本地
`~/Desktop/claude/EchoBird/`（正在同步 upstream 到 v5.6.9），可直接读实现。

- **为什么尚未做**：2026-09-06 刚提出。源码已读完（本地大模型/模型中心/应用管理三块），
  Auto Router 新代码（`src/pages/FreeModels/`）续查中。U-King 已有「免费算力」页，
  Auto Router 应长在它上面而不是另开新页。
- **09-06 源码调查结论（哪些值得抄）**：
  ①「工具探测表」数据驱动：`tools/<id>/{paths.json,config.json}` 每工具两个 JSON，加新工具不改 Rust；
  权威探测器（注册表/MSIX/.app）优先、configDir 只兜底。
  ② 三级降级远程目录：远程 JSON → 磁盘缓存 → 打包兜底，厂商/模型清单可热更、离线不白屏。
  ③ 下载器：多源并发测速（hf-mirror/ModelScope/7 个 GitHub 代理）+ Range 断点续传 + `bin.new/` 原子
  swap + pause/cancel。国内镜像清单本身就值钱。**但它没有 sha256 校验——我们抄时必须补上。**
  ④ 固定端口常驻 relay 代理（53682 axum）：工具配置指向本地代理，真实上游写 relay JSON 每请求热读，
  换模型=写一个小 JSON，不改工具配置不重启。这是统一模型切换最该抄的架构。
  **别抄的**：vLLM/SGLang 是 Linux-only 挂名支持；「测试速度」只是 HEAD 打域名根，测不出 key 有效性；
  硬编码兜底版本号会腐坏。本地模型引擎=llama.cpp 官方预编译二进制（非 Ollama），链路真实可用。
- **09-06 Auto Router 续查结论（v5.6.9 新代码，`smart_router/`，端口 53683 独立于 53682）**：
  核心链路真实可用。值得照抄的六点：
  ① FailureClass 五分类差异化冷却：429→读 Retry-After 否则 60s；5xx/超时→30s 指数退避封顶 5min；
  模型下线（404+14 个关键词）→6h；鉴权/欠费→1h。
  ② **内容审查不计入故障**——命中 content policy 关键词原样透传不切换，否则一句敏感提问烧光全部候选。
  ③ 候选指纹 `hash(model+url+key)` 变了就清健康记录，改完 key 不用干等冷却。
  ④ last_success 粘性 + 45s 总预算分段超时；流式首个非空 chunk 即算成功，断流不再切换。
  ⑤ Anthropic 协议在边界合成（上游只要 OpenAI 兼容，进出各转一次），这是喂 Claude Code 的唯一务实解。
  ⑥ 全挂返回 503 带每个候选的 AttemptRecord，可自诊断。
  **别抄**：免费目录无打包兜底（远程挂了页面全空，我们要带 fallback）；「一键获取」实为拉目录+假扫描
  动画，key 仍要用户去官网注册手填，别学这个话术；候选上限 20 无依据（最坏 45s 试 20 家），定 8-10。
- **落地方式**：本地端点归动作核心管（启停/状态都是动作），前端只是调用方。
- **验收**：本地端点两协议各通一条真实对话；某供应商人为断掉后自动切换可复现；
  探测行为有冷却证据（日志计数），不是每请求都探。

## P2 · 随盘凭据支持用户自填 key（2026-09-06，用户提议）

制盘凭据现有两档：不带 / 写入设备钱包 key（official_device）。用户点名「自己配置是一个可选项」——
第三档：用户粘贴自己的 api key 写进盘上 `.security.yml`。

- **为什么尚未做**：与既有设计红线冲突需先解决——动作核心此前约定「key 只引用不接收」，
  自填 key 意味着 key 要经过 GUI→invoke 入参。需定密钥入参的专用通道（不落命令历史、不进日志、
  schema 标记 secret 字段），而不是简单往 enum 加一档。
- **落地方式**：`credential_ref` 加 "custom"，key 走标记为 secret 的独立字段；CLI 侧只允许
  从环境变量/文件读，拒绝命令行明文；写盘沿用 atomic_write，任何输出/错误信息不回显 key。
- **验收**：自填 key 制盘后精灵能对话；`action run` 命令行传明文 key 被拒绝并提示正确用法；
  日志/stdout/错误全程 grep 不到 key。

## P2 · 开源 U 盘项目复用引导配置壳子（2026-09-06，用户提议）

u-claw 系开源 U 盘项目（`v1-开源/`、`u-king简化版-u盘版本` 等）也要能用同一套「制盘 + 写配置 +
写凭据」引导壳，不各自维护一份制盘逻辑。

- **为什么尚未做**：usb_genie 动作核心目前长在 u-king 仓里，开源盘项目怎么引用（拷贝？子模块？
  独立小 crate？）未定；且开源盘不该带官方设备钱包，凭据档位要按项目裁剪。
- **落地方式**：制盘核心抽成可复用单元，开源项目只配「目标 runtime + 允许的凭据档位」；
  官方 key 档位只在 u-king 商业版存在。
- **验收**：至少一个开源盘项目用同一核心制出可用盘；两边制盘逻辑 grep 无重复实现。
