# U-King「AI 设置」UI 设计规格

**目标：先让用户接通一家模型，再管理多家供应商。** 页面按「虾盘云优先 → 已保存供应商 → 快速添加其他来源」建立层级。

本规格基于当前代码与三张竞品截图；纯设计，不修改代码。侧栏、U-Chat、我的 AI 首页本轮不动。

## 设计依据

已核对 [Manager.tsx](src/Manager.tsx:2083)、[CustomProviderModal.tsx](src/components/CustomProviderModal.tsx:119)、[globals.css](src/globals.css:30)，并阅读 Sidebar、MyAI 和供应商模板。

需要先澄清三点：

- **预填能力已经存在。** `openAddTemplate` 已能预填名称、双协议地址、模型和申请 Key 链接；入口主要在「工具分配」，供应商库缺少同样直接的入口。
- **`addable` 不是中转站推荐榜。** 它表示“可加回当前工具列表的来源”，包含 DeepSeek、GLM、Kimi、Ollama，以及被移出的已有供应商；OpenRouter、OpenCode Zen 来自独立的 `templates`。
- **协议标签与测速结果是两种信息。** 标签来自已填写的地址；当前 `providerLatency` 只探测 OpenAI 端点，不能表示 Anthropic 或具体 CLI 已验证可用。

## A. AI 设置页重排

### A1. 页面骨架：官方渠道置顶，供应商库形成主区与右栏

从上到下排列：

1. **虾盘云官方渠道条**，跨主区与右栏。
2. 现有五个设置分区：供应商库、工具分配、免费算力、用量账单、高级。
3. 供应商库内容：左侧“我的供应商”网格，右侧“快速添加”。

普通进入 AI 设置时默认显示供应商库；从具体工具进入配置时，保留直达该工具分配的路径。五个分区只调顺序和默认入口，不删功能。

| 项目 | 可直接执行的规格 | 价值 |
|---|---|---|
| 间距 | 沿用外壳留白；页内区块间距 24px，左右栏间距 20px，网格间距 12px | 建立稳定的阅读节奏 |
| 字号 | 区块标题 16px/600，卡片名称 14px/600，正文 13px，辅助信息 12px | 替换目前大量 9–10.5px 小字 |
| 表面 | 页面 `bg-0`，卡片 `bg-1`，输入区 `bg-2`，悬停 `bg-3`；边框 `ink-5/30` | 用已有色板区分层次 |
| 控件 | 普通按钮高 36px，图标点击区至少 32×32px；卡片沿用 `rounded-card`，输入框和按钮圆角 8px | 减少同页尺寸漂移 |
| 文字颜色 | 标题 `ink-0`、正文 `ink-1`、说明 `ink-2/3`；`ink-4/5` 不承担必读说明 | 小白能读清下一步 |

### A2. 官方渠道：把余额条与虾盘云卡片合成一处

**位置与形态：** 页顶全宽模块，默认约 112–136px 高，内边距 16px；`bg-1`、1px `accent/30` 边框。保留普通卡片尺寸语言，不做大广告横幅。

- 第一行：**虾盘云**，旁边 12px `accent` 标签“U-King 官方渠道”；说明“免填密钥，充值后在工具分配中启用”。
- 右侧：余额 20px/600；主按钮沿用“充值开通／补充余额”，高 36px、`bg-accent`；刷新为 32px 图标按钮。
- 第二行：沿用现有默认模型、协议标签、延迟及单卡重测；工具引用情况有数据才显示。
- “钱包管理”放右下文字入口；现有钱包操作在此展开，**普通网格不再重复放虾盘云卡片**。
- 今日／近七天数据进入钱包展开区，用量账单入口保留。
- 未加载显示“余额读取中”，读取失败显示“暂未取得余额 · 重试”；不把未知显示为零余额。
- 已被用户移出某工具时显示真实状态，只提供明确的“加回〔工具名〕”；不因突出官方渠道而自动恢复或启用。

**为什么值得：** 充值、状态、模型来源集中在第一视觉区，减少当前“顶部有余额、下方卡片里又有钱包”的重复。

“官方直连（还原）”仍保留在工具分配中，名称写清“恢复工具官方登录”，避免与虾盘云官方渠道混淆。

### A3. 我的供应商：固定卡片阅读顺序

**区头：** 左侧“我的供应商”，下方一句“保存后，到工具分配中选择使用”；右侧保留“测试速度”和“添加供应商”，均为 36px 次级按钮。页面最强的实色按钮留给官方渠道。

**网格：** 每卡最小宽 280px，默认最小高约 200px，内边距 16px。逐行排列：

| 顺序 | 内容与样式 |
|---|---|
| 1 | 名称 14px/600 `ink-0`；自定义项右侧“编辑”，点击区至少 32px |
| 2 | 来源域名，12px `ink-3`；长地址截断，悬停可查看完整安全地址 |
| 3 | “默认模型”及模型 ID，12px；沿用现有等宽字体，长 ID 可查看全文 |
| 4 | `[OpenAI] [Anthropic]`，高 22px、字号 12px，`bg-2`、`ink-2`，同级并排 |
| 5 | 延迟状态及“测试／重测”，整行高至少 32px |
| 6 | 底部工具引用：“正在用于 Claude Code、Codex”；12px `ink-2`，允许换行 |

卡片同排拉齐高度，内容增长时自然增高，不截断工具名称。“内置／自定义”不再另占彩色徽章；编辑权限本身已能表达区别。

**列表分组规则：**

- 继续从现有供应商与 `addable` 合并数据取得完整来源，不能直接把 `addable` 全移走。
- 已保存的自定义来源即使没有 Key，也留在网格，显示“待填密钥”；不能当成尚未添加。
- 未配置的内置候选移入右栏。已有引用、已有配置的来源保留在主区。
- 不将“在某工具列表里”“已填写密钥”“已通过测试”合并成一个“可用”状态。

**延迟层完整保留：**

| 状态 | 卡面文案及颜色 |
|---|---|
| 尚未测 | “未测试 · 测试”，`ink-3` |
| 正在测 | 现有旋转图标＋“测速中…”，保留行高 |
| 成功 | “150 ms · 重测”，数值 `success-400` |
| 失败 | “测试失败 · 重测”，`danger-400`；“查看原因”展开脱敏错误 |
| 没有 Key | “待填密钥”，`ink-3` |
| 仅 Anthropic 地址 | “暂不支持此协议测速”，`ink-3` |

保留卡内点击重测；不把编辑按钮所在的整张卡变成隐形测速按钮。头部“测试速度”继续调用现有批量探测，进入页面不自动测。无可测项时禁用并解释原因。

标签说明写“已配置此协议地址”；测速说明写“本次 OpenAI 接口响应耗时”。绿色表示本次成功，不新增快慢分级，也不推导 Codex Responses 兼容性。

**空态：** 没有其他已保存来源时，用一块约 120px 高的轻空态：“还没有添加其他供应商。可以使用上方虾盘云，或选择右侧来源填写密钥。”下方保留“添加自定义供应商”。

### A4. 右栏值得搬，但要区分“预填添加”与“加回工具”

**位置与样式：** 宽 272px，与“我的供应商”区头对齐；标题“快速添加”，说明“选一家，自动填好地址”。每行最小高 64px，内边距 12px，行距 8px，`bg-1`，悬停 `bg-3`。

每行：32px 加号按钮＋现有图标或中性首字标＋名称／域名＋32px 外链按钮。名称 13px/600、域名 12px `ink-3`。不新增品牌色或下载 Logo。

| 分组 | 本轮放哪些 | 点击行为 |
|---|---|---|
| 首屏模板 | **OpenRouter、OpenCode Zen、OpenAI 官方** | 调用现有模板预填；弹窗直接聚焦密钥 |
| 更多来源 | SiliconFlow，以及模板库中其余来源 | 展开现有 `templates`，沿用运行时数据与原有顺序 |
| 加回当前工具 | `addable` 中的 DeepSeek、GLM、Kimi、Ollama及已有自定义来源 | 明示“加回 Claude Code”等实际目标，复用恢复列表动作 |

已存在的模板来源显示“已添加／编辑”，不继续诱导重复创建；多账号新建仍保留现有确认路径。

这里选择的是**已有模板的入口位置**，不承诺这些服务当前免费或一定可用。CC Vibe、APIMart、WorldRouter、B.ai 不在现有模板里，本轮不上架；若要加入，属于 **需拍板：模板维护与供应商选择**。

右栏建成后，工具分配中的长模板画廊收成“添加其他来源”入口，仍打开同一表单；弹窗顶部不再重复展示整片供应商墙。

**为什么值得：** 用户不必先理解工具分配，再寻找来源；同时避免把“加回工具列表”误认为“模型已经启用”。

### A5. 窄窗口降级

以下宽度均指**扣除应用侧栏和页面留白后的可用内容宽度**：

| 内容宽度 | 布局 |
|---|---|
| ≥ 1200px | 主区三列卡片＋272px 右栏 |
| 900–1199px | 主区两列卡片＋272px 右栏 |
| 600–899px | 取消右栏；“快速添加”变为区头下方折叠区，卡片两列 |
| < 600px | 卡片单列；按钮可换行，弹窗字段单列 |

无其他已保存供应商时，窄窗口的快速添加默认展开；已有来源时默认折叠。全页共用纵向滚动，不给右栏增加独立滚动条。官方渠道始终在最上方。

## B. 添加／编辑弹窗升级

### B1. 把“选择供应商”移到外面，把“填写密钥”放到眼前

当前弹窗宽 440px，顶部先列内置项和大量模板，再出现表单；Anthropic 地址藏在高级区。预填已经完成，但视觉上仍要求用户重新理解整张配置表。

调整为：宽 **560px**，最大宽 `窗口宽−32px`，总高不超过 `窗口高−32px`；表单正文滚动，标题与底栏固定。背景 `bg-1`，内边距 20px，字段间距 16px。

| 入口 | 首屏内容 |
|---|---|
| 右栏模板“＋” | 标题“添加 OpenRouter”等；名称／域名摘要 → **API 密钥** → 预填模型 → “查看／修改连接信息” |
| 添加自定义 | 名称 → 协议地址组 → API 密钥 → 模型 → 高级设置 |
| 编辑已有 | 名称、协议地址、密钥、模型直接可见；不显示模板选择墙 |

模板入口不再重复列模板；“更换来源”回到选择入口。名称、地址始终可修改，不锁死模板。

### B2. 两种协议地址同级展示

将 Anthropic 地址从高级区移入“连接信息”，与 OpenAI 地址同级：

- 两个**全宽纵向字段**：“OpenAI 地址”“Anthropic 地址（可选）”；560px 弹窗不强塞左右双列，以免长 URL 无法检查。
- 两个输入框均高 40px、字号 13px、`bg-2`；右侧各放“粘贴”，宽约 52px。
- 组下统一说明：“按供应商提供的信息填写，至少填写一种地址。”
- 模板没有 Anthropic 地址就留空，不能猜测补齐。
- 高级区仅保留小模型、Codex 专用模型及现有必要说明。

模板路径可以默认折叠这组预填信息；自定义、编辑路径默认展开。

### B3. 密钥输入：默认遮挡，一次粘贴

当前 API Key 输入框没有设置密码类型，也没有粘贴按钮；页顶钱包摘要还有完整 Key 的 `title`。

本轮规格：

- API 密钥输入框默认密码显示；右侧“粘贴”＋眼睛图标，点击区至少 32px。
- 仅用户主动点击眼睛时，在编辑输入框内临时显示；关闭弹窗恢复遮挡。
- 编辑已有密钥时保持原值，输入框显示掩码；不新增“留空保留”的隐含语义。
- 密钥下方展示现有 `key_hint`；有 `key_url` 时显示“获取密钥”。
- 剪贴板读取失败就在字段下提示“请使用 Ctrl+V 粘贴”，不吞错。
- 卡片、列表、钱包摘要、悬停提示、错误详情均不显示完整 Key；移除现有完整 Key 的 `title`。

### B4. 最短路径：粘贴 → 验证并保存 → 去工具分配

模板已有默认模型时：

1. 点击右栏“＋”，自动聚焦 API 密钥。
2. 点击“粘贴”，名称、地址、模型保持预填。
3. 点击主按钮“验证并保存”，顺序复用现有探测与保存能力。
4. 成功后关闭弹窗，新卡片出现在网格；显示“已保存，尚未启用到工具”，附“去工具分配”。

**底栏：** 左侧文字按钮“仅保存”；右侧“取消”和实色主按钮“验证并保存”，高 36px。编辑模式主按钮为“验证并保存修改”；“彻底删除”移入表单末尾的独立低频区，保留现有确认流程。

行为约束：

- 验证中禁用提交及相关字段，文案“验证中…”；失败留在弹窗，不保存。
- 成功只说明本次 OpenAI 接口测试通过，不能写“所有工具均可使用”。
- 模型为空时展开模型字段，引导“获取模型列表／手动填写”；不把返回的第一个模型自动认定为推荐模型。
- 获取列表成功只说明取得列表，不表示 Key 已验证。
- 纯 Anthropic 配置显示“保存”，旁注明“当前不支持此协议测试”，仍允许保存。
- 原始错误默认收起，先显示一句可操作说明；无法判断时写“连接失败，请查看详情”，不猜原因。

**需拍板：** Anthropic 专用测试、按 CLI 验证兼容性，以及保存后自动启用。这些不能由本轮表单排版假定已经具备。当前最短路径以“保存成功并明确引导启用”为终点。

## C. 砍掉清单：最拖观感的 3 个问题

| 当前问题 | 一句修法 |
|---|---|
| **层级混杂：** 网格直接合并 `providers + addable`，未配置内置来源与已保存自定义来源长得一样 | 主区展示已保存／已配置来源，候选放右栏；保留两者真实状态区别 |
| **入口重复：** 顶部余额条、网格钱包、工具分配模板画廊、弹窗模板墙反复出现 | 官方信息合为一处，来源选择集中右栏，弹窗专注填写 |
| **字小且碎：** 9px 协议徽章、10.5px 信息行、27px 编辑按钮和原始错误争夺有限空间 | 必读文字升至 12px，卡片统一六行顺序，错误详情按需展开 |

## D. 与成熟产品的观感差距

仅据所读代码和 EchoBird 截图判断，不能据此评价未实测的 WorkBuddy 全部交互。  
- **视觉尺度还未收敛：** MyAI、侧栏已改善，但 Manager 仍有大量零碎字号与不同圆角；半天最小修法：只统一 AI 设置的字号、间距、按钮和卡片尺寸，不改外壳。  
- **动作结果边界不清：** 保存、加回列表、启用容易被理解成同一件事；半天最小修法：统一三种成功文案，并给保存结果补“去工具分配”。  
- **反馈不够可信：** Manager 的 toast 固定使用绿色成功图标，保存失败也可能套用；半天最小修法：按成功／失败／提示匹配图标与 token 色，错误留在对应字段或卡片附近。
