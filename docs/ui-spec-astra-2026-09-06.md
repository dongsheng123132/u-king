# U-King UI 升级设计规格

目标：让用户一眼看清 **谁在干活、执行到哪、交付了什么、预计花了多少**。借鉴 WorkBuddy 的信息层级，服务 U-King 的 CLI 驾驶舱定位。

本规格基于当前代码阅读，未修改文件、未运行应用。色板实际位于 `src/globals.css`，仓库没有 `src/index.css`。

**设计边界**

- 保留引擎选择器在输入条上；模型选择留在「+」菜单。
- 空态保持「U-King / 更多 AI，你来指挥」＋输入框＋起手词，整块垂直居中。
- 保留 CORE/MORE/LAB 分组、顺序与折叠方式。
- 对话保持居中单列文档流。
- 沿用现有字体、图标及 token，不增加依赖。

以下共 **4 项对话改进＋3 项首页与外壳改进**。每项限定为半天内可独立交付的前端改动；超出已有数据能力的部分明确标为「需拍板」。

**A. U-Chat 对话页**

**A1｜把已有消耗行改成可读的轮次尾注**

现状：`ChatPanel.tsx` 已有输入、输出、缓存、估算人民币与耗时，但使用 `10.5px / ink-5` 居中排列，信息很难扫读。

- **放哪：**现有 `usage` 节点位置，与正文左边缘对齐；上间距 8px、下间距 16px，保持消息列 `max-w-2xl`，即 672px。
- **长什么样：**默认显示「本轮估算 ≈¥0.0234 · 26 秒 · 用量详情」。字号 12px、行高 20px，费用用 `ink-2`，耗时和详情用 `ink-3`；无背景、无描边。金额沿用现有精度规则。
- **交互：**「用量详情」点击展开输入、输出、缓存读写，12px 等宽字体、`ink-3`；不再默认铺一串 token 数字。现有会话累计金额同步改为 12px、`ink-3`，保留原位置。
- **为什么值得：**直接回答“这次花了多少”，比 WorkBuddy 的积分符号更贴近人民币充值，也避免用户把估算当实扣。

**模型徽章需拍板：**当前历史 `UsageItem` 未保存模型名；轻助手的用量事件也只用于遥测。首批先完成 CLI 消耗行整理。若补模型记录，徽章放在费用前，高 22px、水平内边距 6px、`bg-2 / ink-2`、12px，不可点击；只能显示该轮记录的模型，不能用当前选择器倒填历史。“跟随设置”未解析出实际模型时，省略徽章。费用未知不显示 ¥0，上游美元值不作为实扣展示。

**A2｜工具过程降低卡片感，保留明确状态**

现状：成功输出已默认折叠、失败默认展开；问题是每个工具仍是一张独立描边卡，连续执行时视觉重量偏大。

- **放哪：**原工具节点位置，不跨越助手正文合并，不改变事件顺序。
- **长什么样：**普通读取、搜索、命令节点改为轻行：最小高 32px，水平内边距 12px，默认透明底、无独立外框；悬停 `bg-2`。工具名称 12px、`ink-2`；路径和摘要 12px、`ink-3`；图标 14px。
- **状态：**右侧显示图标＋「执行中／完成／失败」，不能只靠圆点颜色。分别用 `accent / success-400 / danger-400`。仅失败节点保留 `danger-500/25` 边框。
- **展开：**继续使用现有整行点击；输出区 `bg-1`，12px 等宽字体，行高 18px，最大高 192px。保留现有截断提示。
- **例外：**Edit/Write 的 diff、产物卡、待审批内容保留原有可见性，不藏进普通过程行。
- **为什么值得：**借鉴 WorkBuddy 的过程收纳，让结果成为视觉主体，同时让失败和待审批仍能及时被发现。

**A3｜增加本轮文件汇总，复用现有预览能力**

现状：已有 `ProducedFile`，支持预览、打开与定位文件，但入口散落在各个工具节点里。

- **放哪：**本轮结束后的消耗尾注上方；只在识别到文件时出现，与正文左对齐。
- **长什么样：**折叠入口「本轮文件（3） ›」，高 28px，文件图标 14px，文字 12px、`ink-2`；悬停文字 `accent`，背景 `bg-2`。
- **展开：**在原位列出文件，不新开抽屉。复用 `ProducedFile` 的检查与操作；列表底 `bg-1`、外框 `ink-5/30`、圆角 6px、内边距 12px。文件名 13px、`ink-1`；路径和大小 12px、`ink-3`。
- **数据规则：**只汇总本轮工具节点已经识别到的路径，按完整路径去重；同名不同目录保留目录说明。没有文件则整行隐藏。
- **为什么值得：**用户做完一轮可以直接取成果，不必倒着翻工具日志。

首批叫“本轮文件”，不叫“所有产物”：当前路径识别带有限制，不能保证完整发现。独立的「查看所有变更」涉及变更聚合，**需拍板，首批不做**；已有内联 diff 继续保留。

**A4｜把已有 Markdown 表格排成清晰的结果表**

现状：`src/lib/miniMd.tsx` 已支持 GFM 表格及横向滚动，无需新增渲染器。

- **放哪：**回答正文原位置；样式限定于聊天区域，避免影响其他使用 `MiniMd` 的页面。
- **长什么样：**表格外框 1px `ink-5/30`、圆角 6px；表头 `bg-2`、正文 `bg-1`。表头 13px 半粗、`ink-0`；单元格 13px、行高 20px、`ink-1`，内边距 10px 12px。行分隔线 `ink-5/20`，不加斑马纹。
- **宽内容：**保留局部横向滚动；路径允许单元格内换行，数字遵循 Markdown 指定的对齐方式，不让长路径撑宽整个页面。
- **状态：**模型原文中的 ✅/❌ 保留，不自动把整行染色，也不把文字判断升级为“系统验证通过”。系统生成的状态另用现有图标＋文字，成功 `success-400`、失败 `danger-400`。
- **为什么值得：**借鉴 WorkBuddy 状态表的可扫读性，同时分清“AI 的陈述”和“工具返回的结果”。

**B. 我的 AI 首页与外壳**

**竞品形态取舍**

| WorkBuddy 形态 | U-King 判断 |
|---|---|
| 场景 tab | 适合选择要做的事；现有 `QuickPrompts` 已具备，继续留在 U-Chat，不复制到工具管理首页。 |
| 能力 chips | 适合填入任务起手词；现有实现已能完成，不再增加一排泛能力标签。 |
| 最佳实践案例卡 | 本轮不采用。首页先解决安装、配置、启动；案例缩略图会占掉关键操作位置，还需要维护真实案例。 |
| 大输入框 | 适合 U-Chat；“我的 AI”保持工具管理职责，避免出现第二个任务输入入口。 |

**B1｜充值引导保留前排，但只突出当前一步**

现状：`XiapanGuide` 已前移；外层主按钮与步骤卡内按钮重复，三张步骤卡同时占据较大面积。

- **放哪：**保留目前位置及显示条件，包括自带 Key、全就绪时隐藏；保留终端恢复提示。
- **长什么样：**外层内边距 16px、圆角 6px，使用平底 `bg-1` 与 `accent/25` 边框，取消渐变和内层三张卡框。
- **层级：**标题 15px 半粗、`ink-0`；说明 12px、`ink-3`。三步变成横向状态行，间距 16px；完成用 `success-400`，当前用 `accent`，未到步骤用 `ink-3`。
- **按钮：**只保留外层当前步骤按钮，高 36px、13px，沿用现有按钮主色；内层重复按钮取消。可用宽度不足 560px 时改为纵排。
- **为什么值得：**充值入口仍醒目，但用户一次只需判断一个下一步。沿用现有收费说明，不增加套餐或计费承诺。

**B2｜已安装工具卡只保留一个主动作**

现状：一张工具卡下方可能连续出现换模型、升级修复、卸载等整行入口，卡片更像设置表单。

- **放哪：**原“我装好的 AI 工具”网格，保留当前排序。
- **长什么样：**卡片 `bg-1`、1px `ink-5/30` 边框、圆角 6px、内边距 16px；取消额外阴影。图标容器从 48px 收到 36px，工具图标 24px。
- **信息顺序：**名称 14px 半粗、`ink-0`；安装状态和模型 12px；实际启动路径保持可见，12px、`ink-3`，单行截断并提供完整路径提示。便携标识保留。
- **操作：**原「打开应用／打开终端」保持高 36px；升级修复改为卡底 32px 轻入口，文字 12px、`ink-2`；换模型和卸载收进旁边「更多」菜单。卸载沿用原确认流程。
- **为什么值得：**先让用户识别工具并启动，修复仍然够得着，维护动作不再占据半张卡。仅“已安装”不能改称“可用”。

**B3｜侧栏提高文字可读性，统一选中态**

现状：侧栏已有 208px 展开态、52px 收起态和短屏适配；副标题常用 10px、`ink-4`，部分分组使用 `ink-5/6`。

- **放哪：**只调整现有导航行、分组标签和底部控件样式，不搬入口。
- **长什么样：**主导航 13px、`ink-2`；副标题与分组标签统一 12px、`ink-3`。普通双行项目最小高 48px，紧凑单行最小高 36px，图标统一 16px。
- **选中态：**统一 `bg-accent/12`＋左侧 2px `accent` 线；名称 `ink-0` 半粗、图标 `accent`。普通悬停 `bg-2`。
- **短屏：**沿用已有隐藏副标题与独立滚动机制；底部图标按钮点击区至少 32×32px，键盘焦点使用 `accent` 描边。
- **为什么值得：**保留已经收敛的信息架构，通过清楚的字和稳定的选中态提升观感。

**C. 砍掉清单：最拖观感的 3 个问题**

| 代码中可见的问题 | 一句话修法 |
|---|---|
| **低对比小字承载关键事实**：消耗用 `10.5px / ink-5`，侧栏说明也偏小。 | 按 A1、B3 把关键辅助信息统一到 12px、`ink-3`，`ink-5` 只留给弱装饰。 |
| **首页重复按钮与维护横条过多**：充值下一步出现两次，工具卡底部多条操作抢占高度。 | 按 B1、B2 每个区域保留一个突出主动作，修复留轻入口，其余收进更多。 |
| **切换引擎像换了界面**：`ChatPanel` 是文档流；`Chat.tsx` 轻助手仍有左右对齐、78% 宽气泡及独立空态区。 | 按本次红线，把普通轻助手的消息容器与空态布局对齐 `ChatPanel`，保留专家信息及原有功能。 |

最后一项属于**落实已定红线的样式修正**：消息统一 672px 居中列，助手正文无气泡底，用户输入沿用左侧细线；普通空态只保留既定品牌、composer 和起手词。可作为独立半天任务，不涉及修改终端 TUI。

**交付验收**

- 1366×768 下，空态整块居中；进入对话后输入区回到底部。
- 连续工具执行时，正文、失败、待审批与产物有清楚的轻重层级。
- 长模型名、长路径、宽表格不会撑破消息列；窄空间允许尾注换行。
- 模型未记录、费用未知、文件未识别时不补造信息；所有新增入口调用已有真实能力。
