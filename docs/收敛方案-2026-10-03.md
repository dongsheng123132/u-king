# U-King 收敛方案（2026-10-03）

> 起因：产品负责人自述「喜欢大而全」。本方案不讨论审美，只做三件事——
> **量化现在有多大、按什么砍、怎么砍能随时退回。**
>
> 本文**替代** `first-principles-review-for-fable-2026-09-06.md` 与
> `first-principles-review-astra-2026-09-06.md`（同一件事的两份审视，见 §3.3）。
> 收敛结论只此一份，不再新增第 15 份文档。

## 0. 先承认一件事：症状不是「功能多」，是「没有准入和退出」

`src/components/Sidebar.tsx` 一共 811 行，其中大半是**入口的增删史**：AI 创作 08-21 摘掉、
08-23 又整块 revert 回来；「我的 AI」这个名字 09-29 从装机页挪到日常页；「专家」「AI 技能」
从侧栏撤掉又合进工作台；GEO 体检查询 0 条却因为「那是一条生意」被恢复……

单次决策看不出问题，连起来看就是：**进得来，出不去；加的时候有理由，删的时候没有依据。**
所以本方案的重点不是砍多少，而是**把「砍」变成有依据、可退回的常规动作**。

## 2. 判据只有一条：**装好 / 配好 / 跑通**

产品自己的定位就是这句（README 首行：「把 AI 开发环境装好、配好、跑通」）。
任何一个入口、工具、页面，先回答它属于哪一条；**答不上来的，就不是核心。**

### 2.1 三问闸门（2026-10-03 产品负责人定）

| 问题 | 取证方式（不许用「我觉得」） |
| --- | --- |
| 现在有真实用户在要它吗？ | 工单/售后记录里的**询问条数** + 安装上报里的**尝试数** + 近 30 天**活跃会话数**。<br>参考先例：GEO 入口恢复前全量翻过两个工单仓 460 条，客户询问 **0 条**、真实使用 **1 台设备 1 次**。 |
| 能不能用现有的三件事表达，而不是新开一块？ | 能否作为「我的 AI / 工作台 / AI 设置」里的一段、一个折叠区、一个已有动作的调用方；<br>不能就说明它是**新的一块**，要单独付入口成本。 |
| 坏了怎么发现、谁来修？ | 自检项（`--selfcheck` 里可见）或上报字段 + 回归跑道（`check-*.mjs`/`regression.sh`）+ 明确负责人。<br>三样缺一 → 不许上首屏。 |

**三问都答不上来 = 不加。** 这条从今天起写进 `docs/需求榜.md` 顶部。

## 3. 处置清单

处置只有三档，全部可退回：

- **冻（freeze）**：代码一行不删，只是不出现在首屏 / 不进默认路径。
- **藏（hide）**：从侧栏或首屏撤下，保留深链可达（页面、路由、动作都在）。
- **摘（retire）**：打归档标签后从仓库删除；只在「证据表 + 退出条件到期」之后才允许。

> 顺序永远是 **冻 → 藏 → 摘**。一步到位地删，是 08-21 那次事故（AI 创作被摘、客户看到「作图功能没了」）的复现。

### 3.2 工具层：「我的 AI」= 已装的 + 4 个推荐，其余折叠

先说清楚：**工具多不是罪**——「一键装好你的全部 AI」就是靠工具清单兑现的。问题是
**二十多张「可安装」卡片平铺在一个页面上、没有推荐顺序**（产品负责人 10-03：「目前推荐的不合理」），
以及**跟 AI 编程无关的日常软件混在 AI 工具里**。

「我的 AI」本来就是「已安装」在上、「可安装」在下（`toolhub/ToolHub.tsx`），所以不用拍一个
「首屏 10 张」的数——**装了的就是首屏**，要解决的只是「可安装」那块怎么排：

| 分组（「可安装」区，自上而下） | 内容 | 默认 |
| --- | --- | --- |
| ① 推荐 | claude-code / codex / hermes / dsh（深度接入、能配模型、有回归的那几个） | 展开 |
| ② 更多 AI 工具 | 其余所有未隐藏的 AI 工具，**含 1.3.5/1.3.6 新加的 mimo-code / kimi-code / codebuddy-code / qoder-cn** | **折叠**，标题带数量 |

- 分类标签（命令行 / 桌面应用 / 智能体 / 实验室）和「多选安装」**照旧平铺**——用户主动筛选时什么都不藏。
- 已有 6 个 `hidden` 的保持不动。工具目录（`tools.rs`）一个不删。
- **更正**：初稿写的「日常软件归已有页面『日常软件与环境』」不成立——那个页面（`Toolbox.tsx`）

  所以改为在「我的 AI」页内单独折叠，不搬家。

  一律先进 ②，等证据表（§5 第 3 步）说谁有人用再升推荐。

### 3.5 配置：装了就配好——这是主业，不是可选项

> 产品负责人 10-03：「我们慢慢也就剩这一步了，就是帮人家安装；配置还不搞好，就喝西北风了。」

所以**不做**「次要工具只装不配」这种分级（初稿审阅时提过，已否决）。装上的工具，能配模型的都要配好。
入口藏得再干净也不减 bug；**bug 真正的来源是每个工具一套手写的配置分支**
（`providers.rs` 1.1 万行，同时写 Claude / Codex / OpenClaw / Hermes 四种 schema）。
减 bug 的杠杆在这里，不在入口数：

1. **一条路写所有工具的配置**：每个工具的配置描述成数据（文件位置、格式、写哪几个字段、怎么读回），
   由同一个写入器执行 **备份 → 结构化 merge → 原子替换 → 读回验证**。加一个工具 = 加一份描述，
   不是再加一段分支。（同类产品的做法也是每工具一份 manifest。）
2. **「配好」的验收是读回，不是写成功**：目标工具自己读到了、或真实端点打通了，才算配好；
   否则卡片上明说「没配上」并给修复入口，不许静默。
3. **能配才配**：配置格式没公开、或要改工具内部数据库的（多数 GUI 应用、日常软件），卡片上写
   「请在应用内选择模型」，不去硬改。这是诚实，不是偷懒。

这是第 1 步之后最值钱的一件事，单独排期（大改 `providers.rs`，要先有每个工具的读回测试兜底），本轮不动。

### 3.6 设备钱包：保留，但只在该出现的地方出现

不放弃——它是收入来源，也是「小白不注册：一键装 → 一键充 → 一键用」的差异点
（纯 BYOK 的免费工具管家，赛道上已有 13.8 万星的同栈对手）。要改的是**它到处冒出来**：

- 现状：「钱包 / 余额 / 充值」散在约 42 个前端文件；体检卡对**用自己 Key 的用户**也显示红色「待充值」+「去充值」
  按钮（`DoctorCard.tsx`）——这正是「干扰大家用 AI」的地方，也跟 §6「体检全绿 ≠ 充值了」同一个病。
- 目标：钱包只住在「AI 设置 → 账号」一处（§5 第 2c 步）；**没充值不是错误**，不标红、不放大按钮；
  只有真的因为余额不足调用失败时才提示（`errorKind.ts` 已能识别这类报错）。
- 第 1 步先做零风险的那一半：体检卡里「未充值」改成中性灰字 + 小号充值链接。

## 4. 长期护栏（这才是防复发的部分）

1. **三问闸门**：写进 `docs/需求榜.md` 顶部，作为每条新需求的必填字段。
2. **一进一出**：新增一个侧栏入口 / 一个首屏工具 / 一份文档，必须同时指定撤掉哪一个。
   发版检查项：**净新增入口数 ≤ 0**。
3. **每个功能必须有退出条件**：形如「某指标在 N 天内为 0，则执行默认动作 X」。
   GEO 那条就是模板（`90 天付费下单为 0 → 删，且连专家包一起删干净`）。
4. **每个首屏功能必须有负责人 + 发现手段**：自检项或上报字段 + 至少一条回归跑道。
   三样缺一，降级到折叠区或实验室。
5. **侧栏硬上限**：核心 ≤ 5、更多 ≤ 4、实验室**只出不进**（进实验室需要写明毕业标准与期限）。
6. **提交前四问**（沿用既有审视里的那句）：删了什么重复实现？保留了什么能力？
   哪个测试能证明用户路径没丢？有没有减少用户步骤？
   —— 只是把代码搬进新抽象、同时增加状态和后台进程，不算简化。

## 6. 明确不建议动的（别为了瘦身砍到骨头）

- **签名信任链 P0**：远端清单能覆盖内嵌清单 = 可执行未验证内容。这是安全问题，先修。
- **体检判断收敛**：体检「全绿」不该等于「充值了、装齐了、没有新版」。这是**正确性**问题，
  跟入口多少无关，先修再谈合并入口——否则只是把两个会误报的入口缩成一个。
- **U 盘纵向闭环**：这是唯一有跨机验收的业务线，也是差异化所在。
- **`actions.rs` 动作核心**：一条实现、多个调用方（GUI/CLI/MCP/U-Chat），**它是「少代码」的地基**，
  不是重复实现。
- **`browser.rs` 的机器调用能力**：那是 CLI/MCP 的能力，跟 `BrowserPanel` 的 UI 是两件事；
  删面板不能顺手删它。
- **既有产品裁决**：本地大模型上左侧、AI 创作回核心位等，是有明确用户拍板的，不由本次瘦身推翻。
