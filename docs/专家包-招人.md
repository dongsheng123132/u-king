# 专家包 · 招人

> 一个文件夹 = 一个人。放进去就是招进来，删掉就是辞退。
>
> 动作：`runtime.expert.inspect`（只读）· `runtime.expert.dismiss`（写，要 `--yes`）
> 实现：`src-tauri/src/expert.rs` · 前端合并：`src/opencodex/experts.ts`

## 为什么有这个

`experts.ts` 里内置 12 位专家，**硬编码**：想加一个人得改代码、重新发版。

而产品做的是**舞台**——让用户把外面的能力（DSH 生态插件、自己写的 persona）招进来当演员。
这就是那条招人通道。

**上层不区分内置与自招**：`ExpertGallery` / `findExpert` / `Chat` 拿到的都是同一个 `Expert`。

## 格式

```
~/.uking/experts/<id>/
  expert.json    必需 —— 这个人是谁、会什么、怎么干活
  avatar.png     可选 —— 头像（没有就用 emoji）
  README.md      可选 —— 给人看的说明，程序不读
```

`<id>` 就是这个人的 id，**必须与 `expert.json` 里的 `id` 一致**。

### expert.json

```jsonc
{
  "id": "geo-optimizer",          // 必需，与文件夹同名，只能 [a-z0-9-]，≤64
  "name": "GEO 优化专员",          // 必需，卡片大标题
  "role": "GEO 优化专员",          // 必需，职称（召唤按钮用「召唤 <role>」）
  "tagline": "查各家 AI 认不认识你的公司，给出能照着做的修复清单",  // 必需，一句话
  "desc": "……",                   // 必需，能力介绍
  "persona": "你是一位……",         // 必需，方法论 + 语气（进 system prompt）

  "emoji": "🔎",                   // 可选，缺省 🧑‍💼
  "byline": "小搜",                // 可选，花名。让它像个人而不是一张功能卡
  "tags": ["GEO", "网站"],         // 可选
  "scene": "营销获客",             // 可选，精选场景分组，缺省「招进来的」
  "category": "营销",              // 可选，分类 tab，缺省「招进来的」
  "skills": ["uking-web"],         // 可选，依赖的技能包 id
  "requires": ["node", "ffmpeg"],  // 可选，需要哪些外部命令才能干活
  "enginePolicy": {                // 可选，缺省 { default: "uking" }
    "default": "uking",            // uking / claude / codex / claude-cli / hermes
    "escalate": "claude"           // 复杂活升级到谁
  },
  "quickPrompts": [                // 可选，最多 8 条「试试这样问我」
    { "label": "体检我的网站", "template": "帮我体检这个网站在 AI 眼里的可见度：" }
  ]
}
```

## 🔴 校验：包里的每个字节都是数据，不是指令

`persona` 会**原样进给模型的 system prompt**——这是注入面。所以 `expert.rs` 对磁盘内容一律不信任：

| 规则 | 为什么 |
|---|---|
| `id` 只收 `[a-z0-9-]`、≤64 字节，且必须与文件夹同名 | id 同时是文件夹名，放行 `.` `/` 等于放行路径逃逸 |
| `persona` / `desc` ≤ 8192 字，短字段 ≤ 200 字 | 够写方法论，不够塞一本书 |
| 拒绝控制字符（`\n` `\t` 除外） | ANSI 转义、零宽字符不该出现在人物设定里 |
| `expert.json` > 64 KB 直接跳过 | 不读进内存 |
| `enginePolicy` 只认白名单取值，认不出退回 `uking` | 它会被前端拿去起进程 |
| 未知字段一律丢弃，不透传 | `Expert` 之外的东西进系统只会变成没人知道语义的字段 |
| 一次最多 200 个包，超了报 `truncated` | 「没看见」不能被读成「不存在」 |

（上限常量：`MAX_PACK_BYTES` / `MAX_PERSONA_CHARS` / `MAX_SHORT_CHARS` / `MAX_PACKS`，
改数字改那里，别改这张表——**以代码为准**。）

## 🔴 `requires` 只声明，不执行

同类产品的连接器有 `init`（「跑这条命令装我」）、`auth`（登录流程）——**我们刻意不抄那两个**。

那些连接器来自官方审核过的市场；而专家包是**用户往文件夹里丢的一个 JSON**。
给它一个「我来跑任意命令」的字段，等于把 `persona` 那个提示词注入面**升级成任意代码执行**。

所以 `requires` 只收**光秃秃的命令名**（`[A-Za-z0-9._-]`），带空格 / 斜杠 / 分号的一律拒 ——
那些形状是在试图表达「命令行」而不是「命令名」。U-King 只负责**查**和**报**，
装的动作留给用户。用例 `requires_takes_command_names_not_command_lines` 守着这条边界。

本机没有的命令进 `missing_tools`，卡片上显示「缺工具」——同 `missing_skills`，
前置报，不等召唤之后才失败。

## 🔴 拒收必须有回音

畸形的包**不会静默跳过**，而是进 `rejected` 并带原因：

```json
{ "rejected": [{ "id": "BadCase", "reason": "文件夹名只能用小写字母、数字和连字符（它同时是 id）" }] }
```

用户往目录里塞了东西却不生效，最坏的处理是一声不吭——他会以为功能坏了，
而我们连「我看见了但不收」都没说。

## 判据非空

`packs` 为空时，靠 `dir_exists` 区分**「查过了确实没人」**和**「根本没这个目录」**。
用例 `empty_roster_still_says_whether_it_looked` 守着。

## 技能依赖前置检查

专家声明 `skills: ["uking-ppt"]` 而本机没同步这个包时，`missing_skills` 非空，
卡片上直接显示「缺技能包」——**而不是等用户召唤之后才失败**。

这是 readiness 原则（回答「能不能用」不是「装没装」），也是 RTK 那个坑的教训：
`installed:true` 形状全对，但裸 `rtk` 不在 PATH，客户开了两天一点没省。

## 辞退

两条路，效果一样：

```bash
rm -rf ~/.uking/experts/<id>                                  # 直接删文件夹
u-king-mini action run runtime.expert.dismiss --yes --input '{"id":"<id>"}'
```

`dismiss` 是 `remove_dir_all`，**错一次就是删错目录**，所以三道闸一道不能少：

1. `valid_id` —— id 同时是文件夹名，放行 `.` / `/` 就是路径逃逸
2. 删之前 `canonicalize` 比对，确认目标**真的在** `experts_dir()` 底下
   （挡符号链接：有人把 `~/.uking/experts/x` 指到 `C:\Windows`）
3. 只删招进来的 —— 内置那 12 位是代码里的常量，磁盘上根本没有它们的文件夹，
   所以「找不到」返回 `Ok(false)` 而不是报错（**幂等**：辞过一次再辞照样成功）

```bash
mkdir -p ~/.uking/experts/demo && cat > ~/.uking/experts/demo/expert.json <<'EOF'
{
  "id": "demo", "name": "示例专员", "role": "示例专员",
  "tagline": "一句话说明这个人干什么", "desc": "详细一点的能力介绍。",
  "persona": "你是一个示例专员，说话直接、给清单。"
}
EOF
u-king-mini action run runtime.expert.inspect --json
```

打开「AI 专家」页，就能看到这位带「已招」标记的新同事。
