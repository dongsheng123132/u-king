## 先读结论

**现在最缺的不是功能数量，而是已有能力能否沿一条清楚的路径用起来。**

用户要的是：打开 U-King，选对本机或 U 盘上的 AI，配一次模型，通过文字对话完成任务；需要终端和文件时再展开。
不应要求他先理解 CLI 引擎、协议代理、三个供应商编辑入口以及数套体检。

请按“删除 > 简化 > 优化 > 自动化”审视，但不要用减少代码量代替产品判断：

- 已做对的动作核心、工具注册表、会话保活、位置与凭据隔离，保持原样。
- 先删重复管理流程和无用外壳，不删用户仍依赖的能力、恢复路径和真实权限边界。
- 先修可证明的失败和错误状态，再做 U 盘配置闭环；不要先开启新代理、新终端、新工作台三条大工程。
- EchoBird/DClaw 是参考，不是需求包。外部项目“有这项能力”不能证明本项目也需要它的实现架构。

## 二、两处应该先处理的具体问题

### 1. 免费路由下载校验重复编码，正确摘要也会失败

**源码确认 + 隔离计算复现，不是网络猜测。** `freerouter.rs::install` 读取文件后，又启动
`certutil / shasum` 取得已经是十六进制的摘要文本，再对 `digest.bytes()` 逐字节做 `{b:02x}` 编码。

本次从源文件读取真实的 `TARBALL_SHA256` 常量，模拟“外部命令返回完全正确的摘要”，结果为：

```text
expectedLength = 64
reencodedLength = 128
validDigestRejected = true
```

这证明当前比较逻辑会拒绝正确摘要；未执行真实下载/安装，也未核实上游文件现在的内容。

**最小改法**：使用已经存在的 `installer::sha256_hex_bytes(&bytes)`，删除外部进程、平台分支、输出文本解析
和二次编码。预期摘要不合法也应报错，不能用 `if len == 64` 把校验变成可跳过的步骤。
新增已知正确字节通过、篡改失败、非法预期摘要失败的确定性测试；已有公共摘要向量测试可复用。
不要再写第三套校验器，也不能以“下载终于成功”为由删掉完整性校验。

### 2. 体检“全绿”不应等于充值、装齐工具、没有更新

**源码确认。** [`DoctorCard.tsx`](../src/components/DoctorCard.tsx) 的 `isAllGreen` 要求钱包 `charged`、不低余额，
Node/npm/Git 全有、报告中所有工具均已安装就绪、更新检查成功且没有新版。这会让健康状态混入商业使用状态和更新提示；
至少“只用自带 Key、未充值平台钱包”也不能全绿。折叠态据此显示“环境有项待处理”。

**最小改法**：健康针对用户实际启用的工具/模型路径；充值、可选工具缺席、有新版是独立信息，不直接等同故障。
也不应把“检测失败/未知”涂成健康。把判断提成小型纯函数，覆盖 BYOK、平台钱包、本地模型、可选工具、
必要运行时缺失、检测未知几类输入即可，不引入一个新的“健康评分平台”。

合并体检卡时同时解决此问题，否则只是把两个会误报的入口缩成一个。

## 四、需求榜中的弱假设，先收窄再做

### U 盘：缺的是“同一套设置能配到盘”，不是另一套产品

现有凭据选择和制作按钮位于 `!selected.installed` 分支；已制盘尚缺补配/改配的 GUI 路径。
`usb_genie::write_config` 是内部函数，不是已经可供设置页直接调用的公开配置 Action。

下一步只补这条闭环：探测盘上实例 → AI 设置/工具分配选中该目标 → 选择供应商与模型 →
由动作核心校验目标身份、写盘并读回 → 盘上 U-King 可启动 → 另一台机器真实对话。

- 不加 U 盘专属模型页、不复制钱包页、不把本机凭据静默当作盘上凭据。
- 已制盘改模型不应被迫重装运行时；新增/扩展最小配置动作，沿用现有原子写入和配置合并。
- 自填 Key 优先复用已有供应商保存/解析入口，让盘上配置动作引用已选供应商；先审计其日志与输出边界，
  **不假定现有存储已经是安全的 secret vault**。确需专用秘密入参时再补最小机制，不先设计全局凭据框架。
- 先让一个真实开源盘消费者使用现有 Action/CLI 和固定构建物，再决定需不需要抽 crate；“未来可能复用”
  不足以立刻拆仓、做 SDK。当前仓本身已经公开；发布档位与是否开源应分开定义，不能把公开代码等同内嵌私钥。

### Auto Router：先决定复用或替换哪一条，不能不断叠代理

当前免费页已挂 `FreerouterCard`，对应本地 8787；Claude 协议桥是 15723，Codex 桥是 15722。
`codex_proxy.rs` 已区分直连与桥接；`providers.rs` 已区分原生 Anthropic 端点与桥接。
因此需求榜“固定 relay 最该抄”“协议翻译是唯一务实解”的措辞都过强。

建议先给出一句决策：新免费路由**替代、增强还是保留**现有 Free Router，旧配置如何迁移/还原。
保持原生协议可直连；仅对协议确实不匹配的路径使用已有桥。不要为了统一 UI，让全部正常直连请求也依赖本地常驻进程。

对已调查出的机制，保留思路、不照搬常数：

- 429/服务异常/鉴权错误分开处理；内容拒绝原样返回，不切换供应商规避其规则。
- “首个非空 chunk”可能只是 SSE 心跳、角色或 usage，不代表已有可用答复；流式状态必须识别语义事件。
  已输出内容或工具调用后不得静默换模型重放，避免混合答案和重复副作用。
- 区分连接/首个有效事件期限与正常长回答时长；不能把“45 秒总预算”直接变成长文硬截断。
- “20 个太多所以改 8–10 个”仍无依据。先用小型受控候选集验证故障切换，按实测预算决定规模。
- 免费档不可静默落到付费模型；所有候选失败时，给出脱敏、可读的原因，而不是无限重试或暴露 Key。

本地模型也先复用既有模型/供应商入口，证明一条本地推理链路。没有模型下载失败的证据前，不先移植多代理测速、
暂停队列和通用下载调度系统；但实际下载时的完整性校验和安全落盘不能省。

### U-Chat：学习 DClaw 的低决策成本，不复制它的功能堆叠

建议复用现有专家、QuickPrompts 和 Composer，让用户先看见输入框、少量真实任务示例、当前模型、附件及权限状态。
不要求先完成“起名—驯化—规矩”多步教学才开始聊天；引擎和高级配置可渐进展开。

引擎（Claude Code 等）与模型（Qwen/GLM 等）不是同一层。更换模型不必更换整个会话引擎。
权限的 ask/auto/full 有真实语义，不能只为少一个下拉就悄悄合并或放宽。

默认模型选择暂时不能依据先前两次 CLI 总耗时下结论：那不是首字延迟测试，不同网关、推理设置也未控制。
Qwen/GLM 的准确模型 ID、当前价格、图像输入和工具调用能力需另外核实；不能由界面显示名或模型自述推断。
先完成配置路径，再用相同任务/端点条件记录首个有效输出、完成率、费用和图片/工具行为，选一个默认，允许手动切换。
本次没有修改默认模型，也不把未经核实的型号与价格写成实现承诺。

## 五、施工顺序与停止条件

1. **交付保护先做。** 保留签名信任链 P0；先封住未验证远端内容可执行的入口并安全回退，再分阶段完善签名发布。
   不能用“先设计统一平台”无限推迟，也不能为简化删验证。macOS 无当前产物真机证据时，先收窄发布声明。
2. **先修确定问题，再做收敛。** 免费路由校验、体检判断；随后统一供应商编辑、体检挂载与预览面板。
   每个小改动单独回归、单独提交，不混入发布版本和终端大版本变更。
3. **完成 U 盘纵向闭环。** 现有目标接入 AI 设置、已制盘改配、盘上启动器、换电脑对话。以真机证据而非“配置文件生成了”结束。
4. **文字交互在现有壳上优化。** 第二个“终端工作台”入口只控制同一工作台布局，不维护另一组会话。
   活跃 cwd 未知就说明未知；“拉出”若是新 PTY，应写成新开终端，不能冒充原会话迁移。
5. **有决定性证据才升级架构。** xterm 6/wterm/Ghostty 不同时开三条线；先有基线可复现问题，再选一个实验。
   Auto Router 先解决与旧实现的关系，再提交最小可验收方案。

每次提交前回答：删了什么重复实现？保留了什么能力？哪个测试能证明用户路径没丢？若只是把代码搬去新抽象、
同时增加状态和后台进程，没有减少用户步骤，就不算完成这次“简化”。已经合理的地方允许零改动。
