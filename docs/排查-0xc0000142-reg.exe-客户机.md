# 排查记录：某客户机弹「reg.exe - 应用程序错误 0xc0000142」

- 日期：2026-10-18
- 现象：Windows 弹窗 `reg.exe - 应用程序错误`，正文「应用程序无法正常启动(0xc0000142)。请单击"确定"关闭应用程序。」
- 定性（当前结论）：**机器/环境侧问题，不是 U-King 产品 bug**。

## 为什么不是我们的 bug

1. `0xc0000142 = STATUS_DLL_INIT_FAILED`：进程被 CreateProcess 拉起来了，但 DLL 初始化阶段失败
   （[微软官方解释](https://learn.microsoft.com/en-in/archive/blogs/winsdk/what-is-up-with-the-application-failed-to-initialize-properly-0xc0000142-error)）。
   常见根因三类：桌面堆耗尽（desktop heap exhaustion）、杀软驱动级拦截、系统文件/运行库损坏。
   共同点：**都是宿主机系统状态，与调用方代码无关**。
2. 报错截图里只有 `reg.exe` 一个受害者。U-King 在同一热路径上还起 `tasklist / ping / powershell /
   curl / cmd`（都带 CREATE_NO_WINDOW），若是我们 spawn 参数的问题，最该炸的是 `cmd.exe`
   （console 子系统，见 [DSH 同类根因](https://github.com/deepseek-ai/deepseek-harness/discussions/10066)），
   不会单点挑中 reg.exe。
3. U-King 对系统工具一律走 `%SystemRoot%\System32` 绝对路径（`installer::system_tool`），
   不存在「PATH 被改坏、reg 是假货」的可能；弹窗标题就是正牌 `reg.exe`。
4. 我们所有 reg.exe 调用都是 **HKCU 读写（右键菜单/卸载表/MachineGuid）**，不需要管理员，
   与「提权失败」无关。
5. 交叉验证：同日另一套无关软件的子进程在同一码 `0xC0000142` 上也起不来——
   指向环境共性而非单一产品。

## 客户机 60 秒自助自检（发给客户，按顺序做）

1. **先点「确定」关掉弹窗**，把电脑**重启**一次再开 U-King。
   一半以上的 0xc0000142 是「桌面堆被跑满」的临时状态，重启即愈。
2. 在桌面左下角搜索框输入 `cmd` → 右键「以管理员身份运行」，粘贴运行：
   ```
   sfc /scannow
   ```
   跑完再跑（同样窗口）：
   ```
   DISM /Online /Cleanup-Image /RestoreHealth
   ```
   看到「成功地完成了修复」/「未找到任何完整性冲突」就算过。
3. 还弹的话：**关掉杀软/安全卫士的实时防护**（360、火绒、电脑管家等）再开一次 U-King。
   不弹了 → 在杀软里把 U-King 目录和 `C:\Windows\System32\reg.exe` 加入信任/白名单。
4. 还弹：换一个 Windows 账户登录（或新建个账户）试一次。
   换账户就好 = 当前账户配置损坏；新建账户测试不弹，就是账户问题，备份资料迁到新账户即可。
5. 最后兜底：设置 → Windows 更新 → 检查更新，把系统补丁打到最新，重启。

## U-King 侧自检/诊断口子（定位时用，不改代码）

- `U-King.exe --envfp`：环境指纹（JSON，非隐私）。关注 `fingerprint_source` 是否为 `reg-fallback`
  （= reg.exe 也读不到 MachineGuid，坐实 reg.exe 起不来）。
- `U-King.exe --selfcheck [out.json]`：无头自检 JSON（环境体检 + skill 加载 + 驱动预设），可发回客服。
- U-King 界面「反馈」里的诊断采集（`feedback::collect_diagnostics`）自带日志尾巴，可整包截图/导出。

## 若未来要「代码侧兜底」（可选加固，非必须）

现状代码各调用点把 reg.exe 失败当「读不到/没注册」降级，不会把产品弄崩——所以这只是降级体验问题：
例如右键菜单 `is_registered` 在 reg.exe 起不来时恒报「未注册」、机器指纹会退到 `reg-fallback`、
装机清单扫描会少一块。若要更稳，可加一层「system_tool 全局失败熔断」：某系统工具连续 N 次
启动失败（含 0xc0000142）就在体检报告里显式给出「系统组件受损，请先修复系统」的人话提示，
并跳过依赖它的体检项，避免用户把系统的锅记到 U-King 头上。优先级低，等客户机自检结论再定。
