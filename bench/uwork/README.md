# uwork —— U-Workspace 办公能力跑道

> 本目录所有任务、人名、公司、文件均为**合成夹具**，不代表真实客户或真实业务。


一句话：**把一件真办公活交给它，它交得出能用的产物吗？**

```bash
node bench/uwork/run.mjs                     # 全部任务，引擎 pi
node bench/uwork/run.mjs --engine claude     # 换引擎（pi | claude | hermes | codex）
node bench/uwork/run.mjs --only cad,mail     # 只跑某几个
node bench/uwork/run.mjs --json              # stdout 只出 JSON
```

## 跟 `推广物料/…/benchmark-v2` 的区别（别混）

| | benchmark-v2（ShadowBench） | 本跑道（uwork） |
|---|---|---|
| 目的 | 给公众号做**多 CLI 公平横评** | 测**我们配好的这台机器**能不能干活 |
| 技能包 | 关（`--no-skills`，比裸壳） | **开**（客户拿到 U-King 后的真实状态） |
| 环境 | 沙箱 HOME、影子网关、锁版本 | 真实 HOME、真实驱动、真实技能目录 |
| 换引擎 | 是核心变量 | 是对照，默认只关心 pi |

两套都留着。要回答「哪个开源 CLI 更强」看那套；要回答「U-King 装完能不能干活」看这套。

## 三条不许破的规矩

1. **判分只看产物**，不看 CLI 在 stdout 里怎么自述。它说「已完成」不算数。
2. **算错就是错**。格式漂亮但合计差 1000 块，客户看不出来，但那是事故 —— 判 fail，不给部分分。
   （0.9.88 那次实测就栽在这儿：188790 写成 189790，格式完全正常。）
3. **报失败**。跑挂了、超时了、判分器自己崩了，都如实写进 `report.json`。全绿的报告一眼就是营销。

## 任务

| id | 测什么 | 硬判据 |
|---|---|---|
| `xlsx` | 脏 CSV 清洗 → 能求和的 Excel | 去重/排除作废对、金额是数值单元格、**合计精确 = 220676** |
| `cad` | 出一张能打开的 CAD 图纸 | DXF 结构完整、≥8 实体、分图层、按毫米画、中文标注在 |
| `mail` | 读已有 Excel → 写催款邮件 | **正文金额与附件一致（188790）**、收件人/抄送/附件/落款 |
| `web` | 抓网页 → 出摘要 | 命中页面真实特征词 ≥3；**抓不到时如实说，不许编** |
| `docx-edit` | 改客户已有的 Word | 改对 + **未改动部件 CRC32 与原件逐字节相同**（重画一份就 fail） |
| `xlsx-chart` | 带图的 Excel | 汇总数算对 + **`xl/charts/` 里有真图表**（贴图/字符画判死）+ 图表引用的是单元格不是硬编码 |
| `pdf` | 出一份能发出去的 PDF | 合法 PDF + **有嵌入字体**（截图版判死）+ 源文件也留 + 正文金额正确 |

## 加分项 vs 硬性项

带「（加分项）」「（观察项）」的 check **不参与 pass 判定**，只把信号记下来给人看
（比如「合计用公式而非手填」「出了预览图」）。硬性项一条不过就是 fail。

## 判分器自己得先被验

改判分器后，**三件都要做**，少一件就会得出冤枉结论：
1. **正例**：拿技能包造出来的标准答案跑一遍，必须 PASS；
2. **反例**：拿一份已知有缺陷的真产物跑一遍，必须 FAIL —— 永远绿的检查等于没检查；
3. **别家形状**：拿**不是我们生成器**产出的文件跑一遍。

🔴 第 3 条是被真 bug 逼出来的（2026-08-04）：`xlsx-chart` 判分器只拿自家 gen-xlsx 的输出验过，
遇到 ExcelJS 产物当场误判两条 —— 它把中文写成 `&#23458;` 数字字符引用（判成「客户名缺失」）、
把 `<c:f>` 写成不带命名空间前缀的 `<f>`（判成「数据硬编码」）。
一份**完全正确**的产物被判死。自己捏的 fixture 验的是假设，不是现实。
